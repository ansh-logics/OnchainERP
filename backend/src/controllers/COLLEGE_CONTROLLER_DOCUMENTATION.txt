===========================================
COLLEGE CONTROLLER API DOCUMENTATION
===========================================

This document provides complete details about all College Controller endpoints,
including authentication, authorization, data formats, and example requests.

===========================================
AUTHENTICATION & AUTHORIZATION
===========================================

ENDPOINT ACCESS LEVELS:
1. PUBLIC: College registration (no auth required)
2. PROTECTED: Requires valid JWT token
3. ROLE-BASED: Specific roles required (admin, super_admin)

Headers for protected requests:
```
Authorization: Bearer <your_jwt_token>
Content-Type: application/json
```

- **contactDetails** (required): Contact information
- **registrationNumber** (required): Unique registration number
- **accreditation** (optional): Accreditation details
- **campusArea** (optional): Campus size
- **totalBuildings** (optional): Number of buildings
- **totalClassrooms** (optional): Number of classrooms
- **totalLaboratories** (optional): Number of labs
- **libraryDetails** (optional): Library information
- **adminDetails** (required): Admin user creation data
  - **gender**: enum ["male", "female", "other"]
- **academicYear** (optional): Current academic year

===========================================
ENDPOINT 5: ADD DEPARTMENT TO COLLEGE
===========================================

URL: POST /api/colleges/:id/departments
Access: Private (Admin of that college or Super Admin)
Description: Add a new department to the college

REQUEST BODY FORMAT:
```json
{
  "name": "Computer Science and Engineering",
  "shortName": "CSE",
  "description": "Department of Computer Science and Engineering offering undergraduate and postgraduate programs.",
  "establishedYear": 2012,
  "hod": "64a1b2c3d4e5f6789abc9999",
  "programs": ["B.Tech", "M.Tech", "Ph.D"],
  "totalSeats": 120,
  "intake": {
    "btech": 60,
    "mtech": 18,
    "phd": 5
  },
  "courseDuration": {
    "btech": 4,
    "mtech": 2,
    "phd": 3
  }
}
```

FIELD DETAILS:
- **name** (required): Full department name
- **shortName** (required): Unique department code
- **description** (optional): Department description
- **establishedYear** (optional): Year department was established
- **hod** (optional): ObjectId of Head of Department
- **programs** (optional): Array of offered programs
- **totalSeats** (optional): Total seats in department
- **intake** (optional): Intake per program
- **courseDuration** (optional): Duration per program in years

RESPONSE FORMAT:
```json
{
  "success": true,
  "data": {
    "_id": "64a1b2c3d4e5f6789abcdefg",
    "name": "Computer Science and Engineering",
    "shortName": "CSE",

    "establishedYear": 2012,
    "programs": ["B.Tech", "M.Tech", "Ph.D"],
```

===========================================
COMMON ERROR RESPONSES
===========================================

1. COLLEGE NOT FOUND (404):
```json
{
  "success": false,
  "error": "College not found"
}
```

2. UNAUTHORIZED ACCESS (403):
```json
{
  "success": false,
  "error": "Not authorized to access this college"
}
```

3. DUPLICATE COLLEGE (400):
```json
{
  "success": false,
  "error": "College with this short name or registration number already exists"
}
```

4. ADMIN EMAIL EXISTS (400):
```json
{
  "success": false,
  "error": "Admin email already exists"
}
```

5. VALIDATION ERROR (400):
```json
{
  "success": false,
  "error": "Please provide all required fields"
}
```

6. SUPER ADMIN REQUIRED (403):
```json
{
  "success": false,
  "error": "Not authorized to access all colleges"
}
```

===========================================
AUTHENTICATION FLOWS
===========================================

FLOW 1: College Registration (Public)
1. Use college registration endpoint (no auth required)
2. Get admin credentials and token from response
3. Use token for subsequent admin operations

FLOW 2: Admin Login
1. POST {{base_url}}/api/auth/login
2. Body: {"email": "admin@college.edu", "password": "admin_password"}
3. Get token from response
4. Use token in Authorization header

FLOW 3: Super Admin Access
1. Login with super admin credentials
2. Access all colleges and system-wide operations

===========================================
VALIDATION RULES
===========================================

1. **College Name**: Required, minimum 3 characters
2. **Short Name**: Required, unique, automatically uppercase
3. **Registration Number**: Required, unique
4. **College Type**: Must be valid enum value
5. **Email**: Must be valid email format, unique for admin
6. **Phone**: Must be valid phone number format
7. **Year**: Must be valid 4-digit year
8. **ObjectIds**: Must be valid MongoDB ObjectId format

===========================================
POSTMAN ENVIRONMENT SETUP
===========================================

Variables to set:
- **base_url**: http://localhost:5000 (or your server URL)
- **admin_token**: (from login response)
- **super_admin_token**: (from super admin login)
- **college_id**: (from college registration response)

===========================================

===========================================

1. **Register College** (Public)
   - Test with complete valid data

   - Test with duplicate shortName/registrationNumber
   - Test with invalid enum values

2. **Login as Admin** 
   - Use credentials from college registration
   - Save token for subsequent tests

3. **Get College Details**
   - Test as college admin
   - Test as unauthorized user
   - Test with invalid college ID

4. **Update College**
   - Test as college admin

   - Test as unauthorized user

   - Test as college admin

   - Test with minimal required data

6. **Get Departments**
   - Test as college admin
   - Test as college faculty/student
   - Test as unauthorized user

7. **Get Statistics**
   - Test as college admin
   - Test as super admin
   - Test as unauthorized user

8. **Super Admin Tests**
   - Login as super admin
   - Get all colleges
   - Access any college data

===========================================
NOTES & BEST PRACTICES
===========================================

1. **College Registration**: This is the first step in setting up the ERP system
2. **Unique Constraints**: shortName and registrationNumber must be unique across all colleges
3. **Admin Creation**: College registration automatically creates the admin user
4. **Role Hierarchy**: super_admin > admin > faculty > student
5. **College Isolation**: Users can only access data from their own college (except super_admin)
6. **Data Relationships**: College is the root entity that links all other entities
7. **Token Management**: Tokens expire based on JWT configuration
8. **File Uploads**: For logo/images, use separate upload endpoints
9. **Validation**: Server-side validation enforces data integrity
10. **Error Handling**: Always check response status and error messages

===========================================
TROUBLESHOOTING
===========================================

**Common Issues:**
1. **Registration fails**: Check for duplicate shortName or email
2. **Access denied**: Ensure user belongs to the college
3. **Invalid ObjectId**: Use 24-character hex strings
4. **Token expired**: Login again to get fresh token
5. **Validation errors**: Check enum values and required fields
6. **Role restrictions**: Ensure user has appropriate role

**Debug Steps:**
1. Check server logs for detailed error messages
2. Verify user role and college association
3. Validate all required fields and data types
4. Test with Postman to isolate client issues
5. Check database for data consistency
